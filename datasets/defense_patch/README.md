# Defense Patch - 答辩场景鲁棒性补丁数据集

> 目标：用最小数据量覆盖答辩演示高风险场景，降低翻车概率

## 一、场景定义与判定标准

### 5类高风险场景

| ID | 场景 | 标签 | 判定标准 | 长度范围 |
|----|------|------|---------|---------|
| P0-A | 日常短句 | Human(0) | 单句无上下文；口语/吐槽/感叹/网络表达 | 3-40字 |
| P0-B | 简短确认 | Human(0) | 对话型回复；可含英文/符号(OK/kk/👌) | 1-12字 |
| P0-C | 正式通知 | Human(0) | 模板化但真实；前缀(通知/温馨提示/请/禁止/将于) | 10-60字 |
| P1-D | 正面评价 | Human(0) | 电商/服务好评语气；"东西不错+物流/服务/包装" | 5-50字 |
| P1-E | 口语化AI | AI(1) | 刻意拟人；停顿词/口头禅/自我修正/含糊结尾 | 20-100字 |

### 4个变化维度（每个场景必须覆盖）

1. **长度桶**: 1-4, 5-10, 11-20, 21-40 (通知/评价可到60)
2. **标点/噪声**: 无标点/全角/半角/重复标点/省略号/表情/夹英文
3. **文体**: 口语 vs 偏正式
4. **主题**: 贴近答辩现场（校园/作业/实验/生活/网购/社交）

## 三、数据格式

### JSONL 格式

```json
{"text": "今天心情不错", "label": 0, "scenario": "p0_casual_human", "source": "manual", "length_bucket": "5-10", "has_noise": false}
```

### 字段说明

| 字段 | 类型 | 说明 |
|-----|------|------|
| text | str | 文本内容 |
| label | int | 0=Human, 1=AI |
| scenario | str | 场景ID (p0_casual_human, p0_short_confirm, p0_formal_notice, p1_positive_review, p1_casual_ai) |
| source | str | 来源 (manual, template, lccc, chatgpt, claude) |
| length_bucket | str | 长度桶 (1-4, 5-10, 11-20, 21-40, 41-60) |
| has_noise | bool | 是否包含噪声（省略号/表情/错别字等） |

## 四、数据质量门槛

### 必须满足

1. **去重**: 完全重复必删；高度相似(只换1字)严格限量
2. **长度分布配额**: 每场景至少覆盖4个长度桶
3. **标点噪声覆盖**: ≥20%含噪声，≥20%无标点
4. **主题贴近答辩**: 含少量答辩现场词汇（数据集/训练/测试/准确率/模型）

### 各场景特殊要求

| 场景 | 特殊要求 |
|-----|---------|
| 简短确认 | 必须覆盖 1-2字、3-4字、5-6字、7-12字 |
| 口语化AI | 必须覆盖 3种风格：犹豫停顿/碎片口语/解释拟人 |

## 六、训练配置

### 合并采样策略

若目标训练集 1000 条，Human:AI = 1:1：
- 防御补丁 400 = 300H + 100A
- core_v2 采样 600 = 200H + 400A（补足比例）

### 微调参数

```python
BASE_MODEL = 'models/bert_v3_core_v2'
OUTPUT_DIR = 'models/bert_v3_defense'

EPOCHS = 2          # 少epoch避免遗忘
BATCH_SIZE = 8
MAX_LEN = 128       # 短句为主足够
LR = 1e-5           # 保守学习率
```

## 八、学术依据

1. 检测难度与文本长度相关，短文本更难 [Callison-Burch et al.]

3. 人类化改写会干扰检测 [Contrastive Paraphrase Attacks, EMNLP 2025]
