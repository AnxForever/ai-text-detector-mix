## 3.1 数据集设计理念

### 3.1.1 现有数据集的不足

在AI文本检测领域，现有的中文数据集存在以下不足：

（1）**场景单一**：大多数数据集仅覆盖问答或新闻场景，缺乏对教育、职场、商业等应用场景的覆盖。

（2）**模型单一**：早期数据集主要采用ChatGPT生成，未能覆盖DeepSeek、GLM、Qwen等国产大模型。

（3）**元数据缺失**：缺少场景、风格、长度分布等结构化元数据，难以进行细粒度分析。

### 3.1.2 设计目标

针对上述问题，本文数据集的设计目标如下：

（1）**多场景覆盖**：覆盖教育学术、职场办公、知识百科、社区互动、商业营销、新闻资讯6个典型应用场景。

（2）**多模型生成**：使用GPT-4、DeepSeek、GLM、Qwen、Claude等多个主流AI模型生成文本。

（3）**完整元数据**：为每条样本标注场景、风格、长度、来源模型等结构化信息。

（4）**平衡分布**：确保人类文本与AI文本的比例平衡，各场景分布合理。

### 3.3.3 生成策略

为保证AI生成文本的多样性，采用以下策略：

（1）**多温度采样**：使用temperature=0.7-1.0的范围，增加生成随机性。

（2）**多样化Prompt**：针对每个场景设计35+个不同主题的prompt，降低主题重复率。

（3）**长度控制**：通过prompt指令控制生成长度，覆盖短文(80-200字)、中文(200-500字)、长文(500-2000字)等区间。

## 3.4 数据清洗与标注

### 3.4.1 清洗流程

数据清洗流程如图3-1所示。

```
原始数据
    ↓
[1. 提示词残留清洗] ──→ 移除"分析请求"、"作为...我"等模式
    ↓
[2. 长度过滤] ──→ 保留80-3000字范围
    ↓
[3. 去重处理] ──→ 基于text_id (MD5)去重
    ↓
[4. 质量检查] ──→ 检查语法错误、重复句子
    ↓
清洗后数据
```

**图3-1 数据清洗流程**

### 3.4.2 清洗规则

主要清洗规则如表3-5所示。

**表3-5 数据清洗规则**

| 规则类型 | 具体规则 | 处理方式 |
|---------|---------|---------|
| 提示词残留 | 包含"分析请求"、"作为AI" | 正则替换或删除 |
| 长度异常 | 少于80字或超过3000字 | 过滤删除 |
| 内容重复 | text_id (MD5前12位)相同 | 保留最新 |
| 格式错误 | 纯数字列表、乱码 | 过滤删除 |

## 3.6 本章小结

本章详细介绍了中文AI文本检测数据集的构建过程。主要贡献包括：

（1）提出了覆盖6个应用场景的分类体系，使数据集更具实用性。

（2）采用多模型、多风格的生成策略，提高了AI文本的多样性。

（3）设计了完整的数据清洗流程和统一的Schema规范，确保数据质量。

（4）最终构建了包含58,563条样本的数据集，人类与AI文本比例约为1:1.15。
